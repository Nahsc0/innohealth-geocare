# Staging deployment and operations

## Provision and release

1. Use an organisation-approved private staging project. Provision PostgreSQL 16 with PostGIS, a TLS endpoint, backups and network restrictions. Restrict the database firewall to the migration runner and API service. Use a separate migration account to create the schema and PostGIS extension. Grant the API runtime role CONNECT, schema USAGE and SELECT/INSERT/UPDATE/DELETE on the application tables only. In hosted mode the API does not run migrations automatically.
2. Generate a persistent Fernet key with `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"`. Store it with the runtime database URL and optional provider keys in the approved secret manager. Use `postgresql+psycopg://` and the host's trusted CA with `sslmode=verify-full` for managed Postgres. Retain the encryption key securely for existing sandbox records and backups.
3. Build the FastAPI image from repository root with `docker build -f backend/Dockerfile -t geocare-api .`. Supply `APP_ENV=staging` and explicit HTTPS frontend origins. Run `python -m backend.core` as a migration job with its own credentials. Supply bootstrap admin credentials only during the bootstrap job. Remove those inputs after confirming sign-in. Run the image on a managed container service with TLS at ingress and a readiness probe at `/health`. Configure forwarding so client IPs are obtained only from trusted ingress, and cap request bodies and request rates at the edge.
4. Connect the authorised Netlify staging project to the repo. Configure its built-in Next.js integration with `NEXT_PUBLIC_API_URL` set to the HTTPS backend and `NEXT_PUBLIC_TILE_URL` pointing to an approved tile service. Keep staging private using the host's access controls. Deploy only a CI-verified revision. This repository has CI and build configuration. A credentialed release pipeline will need the selected cloud project's identity and approvals.
5. Verify HTTPS and origin allowlist, mobile navigation, login, logout, simulation tracking and role isolation. Confirm that `/health` returns `dispatch_enabled: false`. Review published facilities against the approved source. Smoke-test NIPOST with the organisation's test key and routing with synthetic coordinates.

## Operations

- Configure platform monitoring for /health, latency, HTTP 5xx, provider failures, database pool saturation, storage and key expiry. Keep API access logs disabled or redact request paths, bodies and headers. Exclude case content, tracking keys, postcode inputs and exact GPS from telemetry.
- Schedule `python -m backend.core purge` nightly with the runtime database role. The job strips expired case details and messages, and deletes expired sessions and throttle buckets. Audit/status metadata and backups need separate retention and access policies. Coordinate retention approval with the data controller before accepting any patient information.
- For service interruption, display the existing 112 routing guidance, pause sandbox intake at the edge if required and use the last CI-verified image. Investigate with request counts, timing and health probes. Do not restore records with a different encryption key. Test restoration in a private isolated database.
- Facility reports and CSV suppress cells below five. Access reports use public community centroids. Review residual disclosure risk before changing grouping, scope or visibility. Use vetted denominators and population datasets for formal geographic inequality measures.

## Before any operational pilot

Complete a DPIA with the responsible data controller, establish lawful bases and sensitive-data conditions, confirm processor terms and transfers, publish reviewed privacy information, and establish rights, breach and retention procedures. Assess the National Health Act confidentiality and record-access provisions with Nigerian counsel. These are review inputs rather than a certification. [Nigeria Data Protection Act](https://ndpc.gov.ng/wp-content/uploads/2024/03/Nigeria_Data_Protection_Act_2023.pdf) [NDPC implementation directive](https://ndpc.gov.ng/wp-content/uploads/2025/03/NDP-ACT-GAID-2025-MARCH-20TH.pdf) [NCDC legal review of National Health Act confidentiality](https://ncdc.gov.ng/themes/common/docs/protocols/116_1580654680.pdf)

Complete privacy and security review beyond the sandbox controls, including identity lifecycle, MFA, key rotation, access revocation under concurrent load and independent testing. Obtain signed partner agreements, define real incident handoff, coverage, acknowledgements, fallback procedures and release authority. Any operational dispatch integration requires a separate implementation and acceptance exercise. No setting exists to turn this implementation into a live dispatch service.
